Before writing or changing a spec, read the "Specs" section of `AGENTS.md`. A new spec comes from the `spec-clarify` skill; a spec whose work exceeds the PR size guide in `doc/rules/git-workflow.md`, or that mixes concerns, is split with `spec-breakdown` before development starts. A delivered spec (its work merged, for example `specs/001-defra-id-implementation-plan.md`) is never edited — record the change in the new spec and name the spec it supersedes.
